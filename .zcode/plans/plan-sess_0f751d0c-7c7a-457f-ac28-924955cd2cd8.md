# Windows→Mac 反向键鼠共享：实现与测试计划

## 目标

键盘鼠标接在 Windows PC 上时，把指针推过 Windows 屏幕边缘即可控制 Mac：Windows 捕获本机输入、加密转发；Mac 接收并注入。同时**完整保留现有 Mac→Windows 方向**（默认角色不变，角色可切换）。

## 核心架构决策（已验证可行）

**保持网络拓扑完全不变，只反向输入消息流。** 今天的协议里"谁监听/谁外连/谁显示配对码"与"谁是输入发送方"是耦合的；但加密（SecureChannel 双端角色对称，`Wire.swift:94`/`Wire.cs:33` 均有 `isServer`）、组帧、配对、发现都与输入方向无关。因此：

- Mac 继续监听 TCP 24860、继续显示 6 位配对码；Windows 继续外连、继续输入配对码（**配对体验与现在完全相同**）
- **Windows 无需任何防火墙入站规则**（这是方案 a「Windows 改为监听方」被否掉的原因：破坏"Windows 零入站规则"的核心卖点，还要新增整套监听/配对服务端/发现应答端）
- 会话上反向消息流：Windows 产生 `enter/move/moveRaw/button/wheel/key/action/ping/arrangement`（发送方消息），Mac 处理并注入；Mac 产生 `screen/leave/pong(/stats)`（接收方消息）
- 角色用设置切换：Mac「发送方(默认)/接收方」，Windows「接收方(默认)/发送方」；文档将 PROTOCOL.md 的方向标注从"Mac/PC"泛化为"输入发送方/接收方"

两端新增代码正好落在能力缺口上：C# `Messages` 目前只有接收方编码器（`Wire.cs:136-178`），Swift `MessageReader` 缺 `u16()/u32()`、`AppController.handle` 只有接收方分支——都是要补的。

## 阶段 0：协议与测试地基

1. `docs/PROTOCOL.md`：方向标注泛化为输入角色；补遗漏的 `0x17 action` 行；wheel 单位描述改为"接收方换算为自己的滚动单位"；说明本特性。README/ADAPTING.md 同步。
2. **二进制契约 fixtures**：`tests/contract/` 新增 `enter/move/moveRaw/button/wheel/key/leave` 的字节级样例（hex），Swift 与 C# 测试各自编码后比对——两侧都将开始编码从未编过的消息，这是防漂移的关键。
3. Wire 补齐：Swift `MessageReader` 加 `u16()/u32()`；C# `Messages` 补 `Enter/Move/MoveRaw/Button/Wheel/Key/Action/Ping/Arrangement` 构造器；**把 `Wire.cs` 链接进 Unictrl.Tests**（目前 C# 加密/组帧零测试）。
4. 设置扩展：两端 `settings.json` 增加 `role` 字段（现有 decode-if-present 模式，向后兼容）；排列权威移到发送方（Windows 发送模式下编辑器本地生效并广播 0x03，Mac 接收画布改发 arrangementEdit——两端编辑器代码都已存在，只换权威方向）。

## 阶段 1：Windows 发送方

新增 `Native.cs` 声明（已确认全部缺失）：`SetWindowsHookEx/UnhookWindowsHookEx/CallNextHookEx` + `KBDLLHOOKSTRUCT/MSLLHOOKSTRUCT` + `ClipCursor/GetClipCursor` + `GetAsyncKeyState` + `RAWKEYBOARD`。

- **`SenderCore.cs`（纯 C#，无 WinUI/P-Invoke，链接进测试）**：边缘状态机（光标贴近虚拟屏外侧边 + 向外分量 → 进入远程；迟滞窗口防抖，镜像 Mac `InputCapture.swift:576-622` 的语义）；`enter` 参数计算（yMm/edge/open-flags）；scan+E0 → HID usage 反查（用 KeyTable **基础表**反转，0x31/0x32→0x2B 歧义按 VK 区分，单测断言双射）；wheel 换算（±120→lines、水平轴符号取反，镜像 `Injector.cs:151-166`）；caps 状态读取（复用 `Native.CapsLockOn()`，enter 后必发）。
- **`SenderCapture.cs`**：专用 `AboveNormal` 线程 + 消息泵（沿用 MouseProbe/Tray 的成熟模式）安装 `WH_MOUSE_LL/WH_KEYBOARD_LL`；本地模式仅观察边缘；进入远程后 `ClipCursor` 锁边 + `CursorHider.Hide()` + 吞掉本地事件（return 1 不 CallNextHookEx，等价于 Mac tap 返回 nil）；过滤注入事件（`LLMHF_INJECTED` + ExtraInfo 签名 `0x554E4943`，代码里已预留此钩子 `Injector.cs:13-14`）；原始计数来自 Raw Input（扩展 MouseProbe 的注册到键盘 UsagePage=1/Usage=6）；hook 线程只做封帧+socket 发送，**无日志 IO**（LL hook 超时会被系统静默卸钩）。
- 指针模式：默认 `physical`（move，毫米）——Mac 注入绝对事件不走 macOS 加速，`native`(moveRaw) 在 Mac 接收端无忠实等价，实现为可调缩放的可选项。
- UI：设置加角色选择；发送模式下的排列编辑（可拖 Mac 磁贴）；状态显示。
- 本阶段测试：SenderCore 状态机/反查表/换算单测；Wire 二进制契约；C# 进程内 loopback 会话测试（TcpListener + 客户端同进程，补上 C# 侧从未有过的网络层测试）。

## 阶段 2：Mac 接收方

- **`InputInjector.swift`**：`enter` → yMm 换算为 points、在入口边缘定位、`CursorVisibility.hide()` + `CursorShield`（全部现成复用）+ 本地输入看门狗（镜像 CursorHider 200ms：本地真实输入到来→恢复光标，用只观察不拦截的 event tap 实现并按 `eventSourceUserData=0x554E4943` 过滤自身注入）；`move/moveRaw` → 虚拟位置累加 + 绝对 `.mouseMoved` CGEvent（设 deltaX/Y，专用 `CGEventSource(.privateState)`，与 ScrollPoster/SpecialKeys 同模式防自环）；`button` → CGEvent 鼠标键（5 键）；`wheel` → 复用 `ScrollPoster`（像素滚动）；`key` → KeyMap 逆映射（116 项已验证无重复，可直接反转；补 PrintScreen→F13 等缺口）、修饰键走 flagsChanged + 正确的 flag 位、caps 按状态差异应用、重复按下设 autorepeat 标志、held 集合在 leave/断开时全释放；consumer 页 → 媒体虚拟键码（0x48/0x49/0x4A 等）或 NX 事件合成，亮度键首版映射 F14/F15 并在文档标注；`action` → 复用 `KeyAction.performOnMac`；`ping`→`pong`；注入指针越过 Mac 外侧边缘 → 发送 `leave` + 恢复光标。
- `AppController` 角色分支：接收模式不装捕获 tap（只装观察 tap）、隐藏发送方专属 UI；`PeerServer`/配对/发现零改动。
- 本阶段测试：KeyMap 逆映射单测（与 Windows KeyTable 输出集合经共享 fixture 交叉验证）；注入几何（mm→points、leave 检测）；**进程内 loopback 集成测试**（PeerServer ↔ 假客户端，真实 localhost TCP，沿用 WireTests 的 pairing-agreement 模式扩展）。

## 阶段 3：稳健性对齐

发送方 ping 节奏（平时 0.5s、指针在外 10Hz）与 1.5s 超时收指针回家、1.2s 会话接续宽限（复用 Mac 现有语义）；断线/leave 全按键释放；崩溃恢复（ClipCursor 清理、CursorHider 已有下次启动修复）；双向体感参数独立（指针速度/滚轮速度/自然滚动）；重启与登录自启（两端已有机制，验证即可）。

## 阶段 4：工具与验收测试（完善测试）

1. **CI（已就绪）**：现有 workflow 跑 `swift test` + `dotnet test`，新测试自动生效；`Wire.cs` 链入测试项目无需改 CI。
2. **`tools/fake-pc` 扩展出 sender 模式**：连接进来后发送 enter/move/key 流，用于在无 Windows 真机时驱动 Mac 接收端做集成自测。
3. **真机验收清单（与你一起在你的真机 Windows PC + 这台 Mac 上执行）**：
   - 反向配对（Mac 显示码、Windows 输入）→ 角色切换后双向各配对一次
   - 穿越：左/右边缘、不同分辨率下的高度对齐、迟滞无抖动
   - 键盘：全部修饰键左右区分、组合键、按住重复、中英输入法
   - Caps Lock 状态同步（两侧分别开锁）
   - 鼠标：5 键、滚轮纵横两轴、自然滚动方向、滚轮速度
   - 媒体键（音量/播放/静音）、亮度键
   - 断线：拔网线→指针回家无卡键；快速恢复→接续；App 重启、系统重启
   - 崩溃安全：强杀两端进程→光标/Clip 状态恢复
   - 提权窗口输入、登录自启、防火墙零提示（验证核心卖点未破坏）
   - 旧方向回归：切回默认角色后 Mac→Windows 一切如常

## 交付与分支策略

在 fork 上开 `windows-sender` 分支开发，每个阶段结束推送（CI 自动跑双端测试），全绿后合入 main。规模预估：Windows 端约 1,300 行新代码、Mac 端约 1,000 行、双端测试约 800 行、文档更新——分阶段交付，每阶段可独立验证。

## 主要风险与缓解

- **LL hook 延迟纪律**：hook 线程零 IO、AboveNormal 优先级、超时静默卸钩 → 加重装看门狗 + 延迟监测（复用 pointer-report.py 分析）
- **提权窗口**：发送模式沿用现有最高权限计划任务自启；UAC 安全桌面明确不支持（与现状一致）
- **macOS 注入无加速度**：默认走 physical(毫米)模式，native 模式给可调缩放并在 UI 说明
- **映射表缺口/歧义**（0x2B、PrintScreen 等）：共享 fixture 双端交叉测试钉死
- **文档漂移**：阶段 0 一并修正已发现的文档 bug（0x17 缺行、wheel 措辞、ping 单位）
